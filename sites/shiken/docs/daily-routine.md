## 以下、仕様の写し(窓口作成、2026-11-08)


毎日更新を前提にした、shiken-nittei.com の運用ルーティンです。役割の分け方は、文章は窓口（Muse）が責任を持ち、Claude Code は流し込み・データ更新・公開・報告を担います。

## 役割

- **窓口（Muse）**：毎日の記事（特集）の執筆と確定、データ変更の内容の確定、公開後の本番確認、文章ゲートの判定
- **Claude Code（PC側）**：公式情報の定期取得と差分の検出、確定稿の流し込み、テストと文章ゲートの実行、公開、報告
- **オーナー**：例外の承認、新しい試験の追加の判断、サービスアカウント等の資格情報の用意

## 毎日の流れ（目安の時刻、JST）

### 06:30 データの朝チェック（Claude Code）
直近30日以内に「申込締切」「試験日」「合格発表」がある全試験について、公式ページを開いて日程と要項に変更がないか確かめる。
- 変更があった場合：データ（data/sites.json 等、そのサイトの正）を直し、差分（試験名・項目・変更前→変更後・出典URL・確認日）を報告に書く。数字の変更は公式ページで確かめたものだけ。確かめられない変更は反映せず「要確認」で報告する
- 申込の状態が変わる日（受付開始日・締切日・発表日）は、その試験の詳細ページの表示が実態と合っているかも見る
- 合格発表があった試験は、公式の結果（受験者数・合格者数）を取り、合格率のデータを更新する

### 07:00 記事の公開（Claude Code）
- 窓口が前日に、Drive「AI > Muse > 試験日程カレンダー」フォルダへ置いた確定稿（ファイル名：記事_YYYY-MM-DD_<slug>.md）があれば、それを特集として流し込んで公開する。本文は1字も変えない
- 流し込みの前後で、既存の文章ゲート（リポジトリのテスト＋check_text.py を最新の ng_rules.json で実行）を通す。ヒットが出たら公開を止めて窓口へ戻す（自分で書き換えない）
- トップページの「今日の特集」と、関係する試験の詳細ページから、記事への内部リンクを張る
- **確定稿がない日は、記事を作らない**。データ更新と報告だけを行う。薄い記事を無理に出さないための決め（後述の記事の条件）

### 公開後（窓口）
窓口が本番の記事とトップを開いて確認し、問題があれば指摘ファイルで戻す。

## 毎週（月曜日、Claude Code）

- 全試験の公式ページを巡回し、次年度の日程発表（例：宅建の令和9年度）、要項の改定、新しい回の追加がないか確かめる。「未発表」のままの項目は、発表されたものがないか必ず見る
- 公立高校入試の40都道府県について、教育委員会の次年度日程の発表がないか確かめる（発表の時期は都道府県で違うため、毎週の巡回に入れる）
- 新しく載せる候補の試験があれば、勝手に足さず、候補として週次報告に挙げる（追加はオーナーの判断）
- 結果は週次報告（差分があったものだけ具体的に、なかったものは「変更なし」の範囲を明記）

## 毎月（1日、Claude Code）

- 受験料の一覧を公式ページで再確認する（「確認中」の行も含む）
- 合格率データの棚卸し：前月に合格発表があった試験の反映漏れがないか
- サイト全体の健全性：内部リンク切れ、サイトマップの件数、文章ゲートの全ページ走査（本番ではなくビルド成果物に対して）

## イベント連動（随時）

- 申込開始日・締切日・試験日・合格発表日は、その試験を当日の記事の題材の第一候補にする
- 大きな日程変更（延期・中止）が公式に出たら、データ反映を最優先し、その日の記事より先に直す

## 毎日の記事の条件（オーナーの決め、話題の速報と同じ基準）

1. **独自の視点**：記事ごとに角度を1つ決める。誰の、どんな場面の役に立つ記事かを、題と導入に反映する
2. **独自コンテンツ**：出典の要約で終わらせない。自分で作る表、計算、比べ方、手順の組み立てなど、この記事にしかない中身を入れる（例：残り日数から逆算した申込と勉強の段取り表、申込者基準と受験者基準の2つの合格率の換算、県ごとの入試日程の違いの表）
3. **厚さ**：上の2つが入る分量にする。条件を満たせない日は出さない（薄いページは検索で評価されず、自動で noindex 扱いになる例が他サイトであったため）
4. **数字は2件以上の一致で確認する**：日付・金額・合格率は、公式ページか、信ぴょう性のある報道・競合・関連サイトの2件以上の一致で確かめたものを使う。出典の種類と確認日を記録に残す。未発表は「未発表」と書く。推測で補わない（このサイトの土台の決め）
5. **文章のルール**：文章ツールのルール（パターン集＋追記）に従い、公開前に文章ゲートで0件にする

## 記事テーマの回し方（窓口が前日に決める。曜日は目安）

- 月：今週の締切（申込の実務。消印有効と必着、支払い方法、締切時刻）
- 火：お金（受験料だけでなく総コスト。計算機と連動）
- 水：データの読み方（合格率、申込者数と受験者数の推移。自作の表）
- 木：入試（都道府県ごとの違い、保護者の場面）
- 金：段取り（試験日から逆算した表。残り日数の使い方）
- 土：CBT・ネット試験の実務（随時受験の進め方、会場と日程の決め方）
- 日：来週の予定のまとめと、次年度の発表ウォッチ
- イベントがある日は、曜日テーマよりイベントを優先する

## 報告の形（Claude Code → 窓口）

毎日の作業ごとに、Drive の同フォルダへ「日次報告_YYYY-MM-DD.md」を置く。中身：
- データの朝チェック：確認した範囲、差分の有無（あれば試験名・項目・変更前→変更後・出典・確認日）
- 記事：公開した場合はURLと、流し込んだ確定稿のファイル名。ない日は「確定稿なし、記事は休み」と明記
- ゲートの結果：使ったルール version、NG語ごとの件数
- 要確認・判断待ちの一覧
週次・月次は「週次報告_YYYY-MM-DD.md」「月次報告_YYYY-MM.md」で同じ形。
